# Support matrix

| Adapter | Status | Notes |
| --- | --- | --- |
| Deterministic memory | Automated tests pass | Dart 3.13.1; list/read, budgets, opaque references, revision evidence, cancellation, and cursor tests. |
| iOS security-scoped directories | Implementation builds; registered-plugin protocol smoke and controlled traversal pass | Flutter 3.47.1, Xcode 26.2, package and example deployment target 18.2. The iOS 18.2 simulator passed P01–P06 against the registered production handler: version, required-field, cancellation-envelope, malformed/raw/wrong-platform credential rejection, unknown-field, and malformed workspace-lifecycle rejection. Its `nativeTest` scheme also passed stable repeated restore/list plus exact, short, and past-EOF reads (L01/R01), directory-as-file rejection (R02), structured expected revisions with unverified output (R03), never-issued ID (A01), cross-workspace and root-swap rejection (A02), first-entry budget overflow (L02), cursor replay, cap-mismatch, and expiry rejection (L04), in-flight list/read cancellation, duplicate rejection, and deadline expiry (C01/C02), and close isolation plus close/abandon/forget/reconciliation invalidation (C03), along with native `permissionLost`/`notFound`/`unavailable`/`providerFailure` paths (A03); the fixture is compiled only with `WORKSPACE_NATIVE_TEST_FIXTURE`. Swift engine tests prove detach generation fencing and a replacement engine, while XCTest independently drives the production handler through authority/range/snapshot-overflow paths (A01/A02, R01/R02/R03, L03), verifies balanced security-scope acquisition, and fences a live plugin operation during detach before a replacement plugin serves a new request. The dedicated iOS 18.2 compatibility host builds, installs, and launches with the registered production plugin. Physical picker/restart/provider scenarios are not yet claimed. |
| Android SAF trees (API 29+) | Implementation builds; registered-plugin protocol smoke, controlled traversal, and instrumentation pass | Flutter 3.47.1, Android SDK 36.1.0, JDK 21 with JVM bytecode target 11. Android API 24--28 are unsupported because they cannot establish descendant containment. An API 36.1 emulator passed P01–P06 including malformed/raw/wrong-platform credential rejection, plus stable repeated restore/list plus exact, short, and past-EOF reads (L01/R01), directory-as-file rejection (R02), structured expected revisions with unverified output (R03), never-issued ID (A01), cross-workspace and root-swap rejection (A02), first-entry budget overflow (L02), cursor replay, cap-mismatch, and expiry rejection (L04), in-flight list/read cancellation, duplicate rejection, and deadline expiry (C01/C02), and close isolation plus close/abandon/forget/reconciliation invalidation (C03), alongside A03 `permissionLost`/`notFound`/`unavailable`/`providerFailure` paths in the `nativeTest` flavor. Kotlin engine tests prove detach generation fencing and a replacement engine; the plugin instrumentation target also passed controlled `DocumentsProvider` query/read and resource-balance checks. The production APK contains no fixture markers. AYN Thor on Android 13 passed P01–P06, the 28-case registered nativeTest fixture suite, and the five-case controlled-provider instrumentation suite (including fail-closed forged-descendant handling). Picker/restart/provider scenarios are not yet claimed. |

Both native adapters cap one operation at 1,000 entries and 8 MiB. They return
`unverified` when provider coherence cannot be proved. Cloud-provider,
revocation, process-death, mutation, and resource-balance rows remain mandatory
before release.
